# 核心架构与业务设计要求

## 1. 路由与布局设计 (Layout & Routing)
系统需采用多套 Layout 嵌套路由设计：
- **基础 Layout (带左侧导航栏)**：包含 `首页`、`题库页`、`考试查看页`、`数据查看页`、`个人中心` 5 个常驻页面。
- **全屏/空白 Layout**：用于 `用户登录页`、`用户注册页`（居中卡片式设计）。
- **沉浸式 Layout**：用于 `答题页`（隐藏侧边栏和顶部导航，防误触，提供全屏倒计时和交卷按钮）。

## 2. 严密的权限控制 (RBAC)
必须实现**路由级**和**按钮级**双重权限控制：
- **管理员**：最高权限，可见所有菜单和操作按钮。
- **教师**：可见题库管理（增删改）、组卷/试卷管理、考试管理、查看分数统计。不可见系统级用户管理。
- **学生**：仅可见首页、考试列表（只读）、个人中心、答题页、查看个人成绩。
- **实现要求**：
  - 路由守卫 (`router.beforeEach`) 拦截无权限页面的访问。
  - 封装自定义指令 `v-permission` 或权限判断函数，在模板中隐藏无权限的操作按钮（如：学生看不到“删除题目”按钮）。

## 3. 关键流程的状态管理与缓存 (Pinia + 持久化)
针对复杂交互，严禁使用普通组件变量存储数据，必须使用 Pinia 并开启 LocalStorage 持久化（防刷新丢失）：
- **组卷缓存 (`usePaperStore`)**：缓存已选题目列表、试卷基础信息。支持添加、移除、调整顺序，最终点击“发布/保存”时，调用 API 统一提交，成功后清空 Store。
- **答题缓存 (`useExamStore`)**：进入答题页时初始化试卷结构。用户每次选择/输入答案，实时更新 Store 中的答题记录（`{ questionId, answer }`）。支持断点续答（刷新页面不丢失进度），点击“交卷”时统一提交并跳转至结果页。
