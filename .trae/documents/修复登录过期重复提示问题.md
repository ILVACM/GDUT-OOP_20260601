# 修复登录过期重复提示问题

## 问题分析

### 根本原因
当 JWT Token 过期时，前端页面初始化通常会同时发起多个 API 请求（如获取用户信息、获取菜单等）。这些并发请求都会返回错误码 `4101` 或 `4102`，而 `request.ts` 的响应拦截器对**每个失败的请求**都独立执行了以下操作：

1. `userStore.logout()`
2. `router.push('/login')`
3. **`ElMessage.error('登录已过期，请重新登录')`** ← 这就是连续弹出十几条提示的原因

### 涉及文件
- `frontend-Vue/src/utils/request.ts` — 响应拦截器（第 27-33 行）

## 修复方案

### 思路
添加一个**模块级状态锁** `isRedirecting`，用于标记"是否已经触发过过期跳转"。当第一个过期请求触发后，后续请求检测到锁已设置，则跳过弹窗和跳转逻辑，直接静默拒绝。

### 具体修改

在 `frontend-Vue/src/utils/request.ts` 中：

1. 添加模块级变量：
```typescript
let isRedirecting = false
```

2. 在响应拦截器的认证错误处理逻辑（第 27-33 行）中增加判断：
```typescript
if (code === 4101 || code === 4102) {
  if (!isRedirecting) {
    isRedirecting = true
    const userStore = useUserStore()
    userStore.logout()
    router.push('/login')
    ElMessage.error('登录已过期，请重新登录')
  }
  return Promise.reject(new Error(message))
}
```

3. 在用户重新登录成功后，需要重置锁状态。需要在登录页面的登录逻辑中调用重置，或者在 userStore 的 login 方法中重置。

### 预期效果
- 首次触发过期错误时正常提示并跳转
- 后续并发请求静默拒绝，不再重复弹窗
- 重新登录后状态锁正确重置，下次过期仍可正常提示
